# HCLTech Cloud Data Engineer — Practical Portfolio

## Project Overview

This repository contains the practical implementations, source code, execution results, screenshots, and technical documentation based on the HCLTech Cloud Data Engineer Model Question Paper provided by Jain University.

The project covers six major areas: Advanced SQL, Linux, PySpark Data Engineering, AWS Cloud Services, AWS Step Functions, and Microsoft Azure.

## Objectives

- Design relational databases and write advanced SQL queries.
- Perform Linux log analysis, permissions management, and Bash scripting.
- Process structured datasets using Apache PySpark.
- Implement data cleaning, aggregation, and join operations.
- Configure AWS storage, security, monitoring, and event-driven processing.
- Design AWS Step Functions workflows with retries and error handling.
- Explore Azure Data Lake Storage, VM troubleshooting, and data integration.
- Maintain source code, screenshots, and documentation using Git and GitHub.

## Practical Tasks

### Section A: Advanced SQL — Q1 to Q3

- Q1: Database design, table creation, joins, salary analysis, and ranking.
- Q2: Sales analytics, monthly revenue, window functions, and query optimization.
- Q3: Execution plans, indexing strategies, and duplicate email detection.

### Section B: Linux — Q4 to Q6

- Q4: Log analysis, error counting, date filtering, and hourly error analysis.
- Q5: Permissions, groups, CPU and memory monitoring, and large-file detection.
- Q6: Bash backup automation with validation, timestamped archives, and error handling.

### Section C: PySpark — Q7 to Q9

- Q7: DataFrames, filtering, annual salary calculation, grouping, and sorting.
- Q8: CSV processing, duplicate removal, missing-value handling, date conversion, and revenue aggregation.
- Q9: Customer and order joins, customers without orders, city-level aggregation, and performance concepts.

### Section D: AWS Cloud Services — Q10 to Q12

- Q10: S3 bucket configuration, IAM policies, access verification, and encryption.
- Q11: EC2 troubleshooting, network connectivity, CloudWatch alarms, and CPU investigation.
- Q12: Event-driven CSV processing, Lambda, permissions, logging, and duplicate-processing prevention.

### Section E: AWS Step Functions — Q13 to Q14

- Q13: Sales-processing state machine, Choice states, Retry, Catch, and execution history.
- Q14: Sequential task execution, retry policies, error handling, and workflow testing.

### Section F: Microsoft Azure — Q15 to Q17

- Q15: Azure Data Lake Storage Gen2, Microsoft Entra ID, and role-based access control.
- Q16: Virtual machine troubleshooting, network security, routing, and secure connectivity.
- Q17: Data integration, CSV ingestion, date-based organization, data cleaning, and monitoring.

## Security and Best Practices

- Never commit AWS credentials, passwords, API keys, or private tokens.
- Use least-privilege access policies.
- Use sample or synthetic datasets where possible.
- Exclude virtual environments, temporary files, and unnecessary generated outputs.
- Verify code and configurations before committing.
- Document actual execution results and clearly identify tasks that have not yet been tested.
- Remove temporary cloud resources after testing where appropriate.

## Execution and Verification

Each practical will be executed and verified using the relevant tools and services.

Verification may include SQL query results, Linux command output, PySpark DataFrame results, AWS resource configurations, workflow execution history, and Azure access or pipeline tests.

Cloud implementations depend on available account permissions and training-lab restrictions. Where live execution is unavailable, the limitation will be documented.
